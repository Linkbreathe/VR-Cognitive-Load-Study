# Stage 1 / N-back VR 任务平台

本项目实现独立任务平台，不接入 EEG、ECG、眼动、VLM，不自动调整难度。本阶段仅检验任务平台是否准确、可重复；不能据此声称已验证认知负荷差异或专利效果。

## 打开与操作

Unity 版本：6000.3.27f2。打开 `Assets/TaskPlatform/Scenes/NBackExperiment.unity`，点击 Play。界面使用英文；下面给出中文操作步骤。

| 操作 | Quest 控制器 | 编辑器键盘 |
|---|---|---|
| 匹配 | 右手 A | A |
| 不匹配 | 右手 B | B |
| 确认、进入规则、开始区块 | 左手 X | Enter |
| 暂停、继续 | 左手 Y | P |
| 准备阶段重新放置任务区 | 左手扳机 | C |
| 暂停后终止并新建会话 | 左手扳机 | C 或 R |

双键同时按下不计分；持续按住不会重复回答。试次边界所在帧的按键被保守拒绝，避免上一题输入计入下一题。每题仅接受第一次有效按键。头显应用失去焦点或退到后台会暂停，需要明确继续。

准备页依次完成校准、A/B 检查后才能继续。任务区按当时水平朝向放置在头部前方 1.5 m，与当时眼高一致，随后固定在世界坐标。校准只允许在准备阶段，正式区块中不能移动任务区。

## 一次实验的步骤

1. 实验者确认配置版本、随机种子、区块顺序，记录匿名受试者编号与本机会话目录的对应关系。当前应用不收集姓名。
2. 受试者坐稳、戴好头显，调整到舒适位置。向前看，按左扳机校准任务区；依次按 A、B，确认准备页出现三个 OK，然后按 X。
3. 阅读 0-back 练习规则：蓝色回答匹配，其他颜色回答不匹配。按 X，观看两个不计分刺激，然后完成 8 道练习。练习显示正确答案。对所有预热刺激只观察、不回答。
4. 阅读 2-back 练习规则：当前颜色与两次之前相同则匹配。例如蓝→橙→蓝，第三项匹配。按 X，先看两个预热刺激，再完成 12 道练习。两个练习区块均保留 2 个预热，便于统一实现。
5. 实验者确认受试者理解规则。如果尚未理解，在暂停状态按左手扳机（键盘 C 或 R）新建会话并重新练习。当前版本没有“重复单独练习区块”快捷功能。
6. 阅读第一个正式区块规则，按 X 开始。2 个预热 + 30 道计分题，共 96 秒。正式阶段没有逐题反馈、提示音、亮度变化。
7. 休息至少 25 秒。页面显示下一规则，倒计时结束后按 X 进入规则页，再按 X 开始第二个正式区块。
8. 完成第二个 96 秒区块后显示完成提示。请先确认日志保存，再取下头显。再次按 X 创建新会话；不覆盖旧数据。
9. 实验者导出会话文件，用下方工具重新计算指标，检查配置、漏答、暂停和时序偏差。

纯刺激呈现共 264 秒（练习 30+42，正式 96+96），加休息 25 秒为 4 分 49 秒；规则阅读、输入检查和暂停时间另计。顺序默认为 Easy→Hard；`hardFirst=true` 则正式区块 Hard→Easy，练习顺序不变。

## 时间与评分

每题 3 秒：0–1 秒显示圆球；1–2.5 秒圆球隐藏但可回答；2.5–3 秒不接收答案。提前回答不提前换题。正式每区块恰好 10 道匹配、20 道不匹配，答案从颜色序列自动计算。

每个区块独立生成序列并重置历史。随机生成使用固定实现的 xorshift32 + Fisher–Yates；块种子 = 会话种子 + 区块编号 × 104729（32 位整数）。相同配置和种子可重放。随机打散不承诺绝无偶然连续模式；本版不额外施加未指定的连续次数限制。

暂停冻结题目进度，恢复后继续剩余时间；受影响的题目标记 `interrupted=1`。RT 按程序实际开始到回答的真实时间计算，包含暂停；分析时同时输出全体已完成题和排除中断题的 clean 指标。超过 250 ms 的主循环停顿自动暂停，不静默跳题；设备性能需另行验收。

正确率 = 正确题数 / 计分题数（漏答视为错误）。平衡正确率 = (匹配题召回率 + 不匹配题召回率) / 2；漏答不能当作正确“不匹配”。RT 汇总使用答对且有回答的题目。中止中的未完成题另列，不混入完整题分母。

## 配置与接口

默认文件：`Assets/TaskPlatform/Config/default-task-config.json`。颜色索引为 0 蓝、1 橙、2 绿、3 洋红。几何默认直径为 `2 × 1.5 × tan(3°)`，约 0.157 m；无高光、运动或后处理。

回答映射由 `matchAction` / `nonmatchAction` 指定（默认 RightPrimary / RightSecondary，可互换）；继续和暂停由 `advanceAction` / `pauseAction` 指定。动作定义保存在 `TaskControls.inputactions`，预先绑定 Oculus Touch 和 Quest Pro Touch 的具体布局，符合 OpenXR 启动时注册动作的要求。不同操作不能映射到同一动作；修改动作资源后需要重新构建。

设备可在 `Application.persistentDataPath/task-config.json` 放置完整覆盖配置，然后重新启动应用。一次会话开始时深拷贝配置并写入 session.json；运行中编辑配置不会改变已生成的题目。修改配置时增加 version，重新启动会话。

`TaskEngine.RequestDifficulty(TaskMode, now, frame)` 是预留接口：只允许 Preparation / Instructions / Rest 阶段改变下一个区块；Running / Paused 拒绝并记录事件。这样切换只发生在区块边界，重新提供预热并清空历史。第一版不实现题中自动切换。

## 数据位置与导出

桌面编辑器测试路径：`%USERPROFILE%/AppData/LocalLow/EvidenceVR/Evidence-Aware VR Task Platform/TaskPlatformData/editor-test/<sessionId>/`。实际构建程序使用 `participant` 子目录；`sessionType` 同时标记数据来源。自动验证样例另存于项目的 `Evidence/SyntheticSessions/automated/`。

Quest 路径：`/sdcard/Android/data/com.evidencevr.taskplatform/files/TaskPlatformData/participant/<sessionId>/`。

| 文件 | 内容 |
|---|---|
| session.json | 唯一会话号、UTC 开始时间、程序/Unity 版本、配置快照、完成状态 |
| trials.csv | 正式逐题记录，含预热、漏答、中断和中止标记 |
| practice_trials.csv | 独立练习记录 |
| events.jsonl | 刺激出现/消失、回答截止、按键接受/拒绝、规则、暂停、恢复、帧间隔 |
| summary.json | 运行分析工具后生成的区块指标 |

事件使用 `Time.realtimeSinceStartupAsDouble` 单调时间、计划时间、实际处理时间、偏差和帧号。它们是软件事件，不是头显实际发光时刻。frame_gap 是软件帧间隔诊断，不等同于设备合成器掉帧率。事件逐行刷新，异常强制结束可能保留 `in_progress` 状态，不能当成完整实验。

```powershell
adb install -r Builds/Quest/EvidenceVR-Stage1.apk
adb pull /sdcard/Android/data/com.evidencevr.taskplatform/files/TaskPlatformData ./ExportedSessions
python Tools/summarize_session.py "完整的会话目录"
```

ADB 需要头显开启开发者模式、连接 USB，并在头显内允许调试。使用本机 Unity Android SDK 中的 adb 也可以。

## 重新构建与验证

Unity 菜单 `Evidence VR / Run Automated Validation` 生成 `Evidence/automated-validation.txt` 与 `Evidence/SyntheticSessions/`。这些样例明确标注为合成数据，不可用作受试者结果。

`Evidence VR / Configure Quest Android` 配置 OpenXR、Meta Quest 支持、Touch / Touch Pro 控制器、ARM64、IL2CPP 与 Vulkan；`Evidence VR / Build Quest APK` 输出 APK。XR 设置依据本项目 OpenXR 1.19.0 源码及 [Meta 官方 XR 配置说明](https://developers.meta.com/vr/documentation/unity/unity-xr-plugin/)。

实际交付状态见 `Docs/验收记录.md`。必须完成 Quest 实机检查后才能冻结为通过验收的 Stage 1 版本。
